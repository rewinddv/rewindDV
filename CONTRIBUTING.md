# Contribution proposal

DRAFT — NOT PUBLISHED; no new contributor agreement is imposed.

Prefer small changes supported by a concrete production path and a reproduced failure. Preserve original received bytes, unknown identity/continuity, and the distinction between synthetic tests and physical qualification. Include a focused regression and record what ran, what failed and what remains untested.

Use the file's existing license and retain upstream copyright, notices and modification attribution. State where copied/adapted material came from, its exact revision and redistribution terms. Do not submit licensed standards text, proprietary SDK material, private captures or another person's data without permission. A behavioral reference is not the same as an adapted source implementation.

For reports, include the app alpha, driver build, anonymized hardware route, expected/actual result and sanitized reproduction steps. Inspect every attachment under [PRIVACY](PRIVACY.md). Request a private reporting channel through the existing project issue process when the report cannot safely be public; no unverified contact address is supplied here.

Ordinary contributions under the existing license are the proposed default. A DCO-style sign-off is an owner decision: it certifies contribution rights, is not an assignment or blanket relicensing permission, and publishes its metadata. A CLA should be considered only for a concrete need with separately reviewed terms. Do not publish a contributor's personal metadata merely to test a policy.

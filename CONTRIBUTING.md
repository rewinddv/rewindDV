# Contributing to rewindDV

Report bugs and compatibility results through
[issues](https://github.com/rewinddv/rewindDV/issues), and propose source or
documentation changes through [pull requests](https://github.com/rewinddv/rewindDV/pulls).
Use the same repository for source, downloads, reports and contributions.

Prefer small changes supported by a concrete production path and reproduced
failure. Preserve original received bytes, unknown identity and continuity, and
the distinction between synthetic tests and physical qualification. Include a
focused regression where relevant and record what ran, failed or remains untested.
See [BUILDING](BUILDING.md) and [TESTING](TESTING.md).

For reports, include the app alpha version, driver build, anonymized hardware
route, expected/actual result and sanitized reproduction steps. Use the
[test-report template](TEST-REPORT.md). Do not post support ZIPs, raw logs, footage,
personal paths or device identifiers. Inspect attachments under [PRIVACY](PRIVACY.md)
and request a private transfer channel through an issue before sharing sensitive
evidence. Public project contact: info@rewinddv.com.

Use each file's existing license and retain upstream copyright, notices and
modification attribution. Identify adapted material, its exact revision and
redistribution terms. Do not submit licensed standards text, proprietary SDK
material, private captures or another person's data without permission. A
behavioral reference is not the same as adapted source code.

No new contributor agreement, DCO sign-off requirement or copyright assignment
is introduced by consolidation. Existing license terms continue to apply.
See [release policy](RELEASING.md) for future publication and historical tags.

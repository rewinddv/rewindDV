# Current development: Beta 0.1.22 / App212 / retained Driver203

The canonical product identity is `Config/ProductIdentity.json`. App212 requires
Driver203 and its original driver version 0.1.11. The exact signed public-source
Driver203 is retained without rebuilding, re-signing or relabelling it.

The current implementation includes the recorded camera and supplemental metadata
decoder, source positions and validity, full pack catalogue, searchable inspector
browser, persistent Capture and Playback tabs/filters, and reliable repeated file
chooser operation. See [recorded metadata](Docs/RecordedMetadata.md). Reserved,
absent, manufacturer-specific and disputed values remain explicit; catalogue
coverage is not a claim of complete semantic decoding or IEC certification.

Capture preserves received/raw evidence. Startup/tail classification affects
retained viewing ranges and derivatives without rewriting originals. Recovery,
archive, playback, Surgery and export share the accepted implementation. Full-file
coordinate indexing and forensic assessment remain explicit operations rather
than prerequisites for playback; estimated coordinates remain labelled until an
exact scan establishes them. Continuous displayed-pixel/inspector association
in mixed-format signed-app playback remains unqualified.

The normal CLI exposes 66 app-owned tools over a same-user local socket. It uses
bounded worker I/O, GUI operation guards and supervised STOP. Sandbox path grants
remain session-scoped. Driver activation and physical recovery are interactive.

The complete package suites passed 590 Swift tests and 14 XCTest cases. Native
saved-file/media, archive, ownership/DMA/drain/recovery regressions and 328 driver
host tests passed. These are offline software checks, separate from actual signed
application interactions and physical qualification. A supplemental small-input
progress test coalesced intermediate telemetry; preserved output bytes matched
fixture expectations and the unchanged larger-input assertions passed.

Historical successful PAL captures and a completed whole-tape NTSC workflow remain
scoped to the tested earlier builds in the public
[compatibility record](https://github.com/rewinddv/rewindDV/blob/main/COMPATIBILITY.md).
No new physical Driver203 capture/endurance or live unload qualification is claimed.

Public source is a reviewed content projection with portable signing and privacy
transformations. Canonical `PROJECT-STATUS.json` records development source and
published downloads independently. Exact signed/notarized release provenance
identifies the compiled public commit and retained driver source; development
signing alone does not establish distribution or hardware qualification.
